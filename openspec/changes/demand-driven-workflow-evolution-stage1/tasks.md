Owner labels:

- `[A]` Developer A, Create Loop Catalog/runtime owner; task 0.8D is the sole named exception for an existing Git Checkpoints baseline-correctness semantic repair
- `[B]` Developer B, Workflow Evolution owner
- `[I]` integration/platform hat, not a third developer; for all of Stage1 this hat is owned by Developer A

Every task has exactly one author. A task may require the other developer's review, but review does not transfer authorship or path ownership. `[I]` changes only generic Host/SDK/Broker/CI/generator/integration files and never authors Catalog or Workflow Evolution semantics. Tasks 0.8M, 0.8C, and 0.10R are the only repository-wide `[I]` migration exceptions. Task 0.10R may change package code only to replace an existing resource acquisition with the behavior-preserving generic Host primitive named by its signed lifecycle declaration; it may not change a handler contract, payload, business branch/policy, domain state/schema, retry semantics, or user-visible outcome. Both developers and the recorded owner of every affected package review its diff. Task 0.8D is an independently authored `[A]` Git Checkpoints semantic commit that repairs only the named baseline success envelope and idempotency regression; `[I]` must integrate that exact commit unchanged in 0.8I and may not absorb it into a migration.

Branches and shared files:

- `[A]` works on `stage1/a-<task>-<topic>`, `[B]` on `stage1/b-<task>-<topic>`, and `[I]` on `stage1/i-<task>-<topic>` or `stage1/i-train-<task>`.
- Only `[I]` updates root lock/toolchain files, generated installed-domain composition, generated capability documentation, the generated Stage1 contract matrix, cross-package harnesses, and checkboxes in this file.
- A/B feature branches never edit generated/shared checklist files. After an owned implementation/train PR merges at an immutable SHA, `[I]` records its evidence and marks checkboxes in one separate phase-close checklist PR; CI reruns on that final checklist SHA.

The integration-train protocol is mandatory whenever a change affects package metadata, a manifest or dependency, renderer contribution, capability descriptor or wire schema, public export, generated contract source, or root lock/generated output. An ordinary package-owned implementation change that leaves all of those surfaces unchanged uses its normal A/B feature PR:

1. the domain owner creates an immutable semantic commit from the latest `stage1/integration`, changes only owned files, and passes focused tests;
2. `[I]` creates `stage1/i-train-<task>` from that same integration SHA, integrates the exact semantic commit without rewriting it, runs every required generator, and adds one separate mechanical generated/lock commit;
3. only the combined train branch opens the merge PR to protected `stage1/integration`; full CI and generation-drift checks run on that combined PR, so a semantic PR is never merged while knowingly stale;
4. both developers review the combined diff; if generation exposes a semantic defect, the train stops and returns to the domain owner instead of letting `[I]` patch domain code.

## 0. Collaboration, contract, and generic platform gate

The following clauses are normative acceptance criteria of the named tasks, not later cleanup work:

- `0.3` changes Create Loop's signed definition/export surface by adding `./catalog-contract`, so it SHALL raise both package and module release SemVer from `1.0.0` to exactly `1.1.0` before regeneration; same-version digest drift is forbidden.
- `0.4` introduces the zero-contribution Workflow Evolution shell at package/module version `1.0.0`. `2.1` changes that signed definition from zero contributions to the production backend and SHALL raise both versions to `1.1.0`; `8.3` adds the first renderer/export definition and SHALL raise both versions to `1.2.0`. - `0.4` SHALL freeze `RedactedAgentUsageProjectionV1` as a closed object containing exactly `schemaVersion: 1`; bounded UTF-8 `runtimeVersion`, `modelVersion`, and `profileVersion`; terminal `status`; safe-integer aggregate `inputTokens`, `outputTokens`, `costUsdMicros`, and `latencyMs`; a non-empty, at-most-128, UTF-8-byte-lexically sorted duplicate-free `receiptDigests` list of lowercase SHA-256 values; and `projectionDigest`. Version strings are `1..128` UTF-8 bytes; token/cost/latency totals use the corresponding `RunBudgetDecisionV1` maxima. `projectionDigest` is lowercase SHA-256 over RFC 8785 UTF-8 canonical bytes of every field except itself. Unknown fields, non-canonical numbers/order/bytes, duplicates, and every handle/thread/turn/principal/provider/prompt/result/correlation/sealed/secret field are rejected. `0.6` SHALL freeze accepted/rejected byte vectors for every field/bound, ordering, canonicalization, self-digest exclusion, unknown/duplicate/tamper rejection, and unrepresentability of forbidden data.

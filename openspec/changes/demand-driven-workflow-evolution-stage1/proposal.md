# Change: Add demand-driven Workflow evolution Stage1

## Why

SciForge already has a package-owned Create Loop editor and runtime, but it has no immutable Workflow release/catalog model and no durable requirement-to-promotion controller. The current `WorkflowV1` mixes graph definition with mutable execution history, its global settings revision changes during ordinary execution, and its human approval waiters are in memory. Those mechanisms cannot prove that the object verified, promoted, replayed, and served is the same frozen artifact.

Stage1 needs a smaller, auditable target than general source-code self-modification: one workspace-scoped Workflow Catalog with one stable Anchor and at most one controller-active Candidate lease in the Workflow Evolution Ledger, governed by durable requirements, evidence, independent verification, explicit human promotion, compare-and-swap, replay, and rollback. Create Loop may retain multiple immutable Candidate artifacts for history and stale-write defense; that is not population search.

The updated design is the authoritative engineering skeleton because it closes ownership, authorization, recovery, and activation semantics that the earlier version left implicit. The earlier version is better only as a shorter explanation and as a reminder to preserve early parallel development; its authorization chain, crash recovery, Verifier isolation, and executable fault testing remain non-negotiable safety constraints. This change therefore keeps the updated contracts while separating development, foundation-merge, and capability-activation gates.

## What Changes

- Add immutable V1 Workflow definition, proposed/official Release, stable ServiceBinding, Catalog revision/patch, Candidate/disposition, and stable/pending Anchor contracts owned by Create Loop; keep one execution engine and delete the superseded mutable production path after every caller migrates to current-Anchor bindings.
- Migrate all thirteen current domain manifests to strict `DomainPackageManifestV2` and enroll the complete current release cohort in `sciforge.official`: every one declares package-owned `defaultInstalled:true` and `defaultEnabled:true`. The new backend-first `@sciforge/domain-workflow-evolution` uses the same metadata, so the metadata-derived cohort is thirteen before B and fourteen afterwards. Product classification remains separate: the six existing Workbench packages stay the six existing Workbench packages, and Workflow Evolution becomes the seventh Workbench package; the other seven current release-cohort packages retain their existing classification and every existing contribution. Release configuration selects only the channel, never a package list or count.
- Bind every signed inventory member to standard package name, stable module ID, the one `module.version === package.json.version`, manifest definition digest, canonical target-neutral public-contract export descriptors, closed numeric release-SemVer dependencies, package-owned defaults, and a complete sorted `outboundSystemCapabilities` caller-edge inventory. The one closed Ed25519 inventory envelope reuses the strict purpose-aware `OfficialVerificationKeyV2` keyring, whose exact single usages are `official-extension-package | distribution-inventory | agent-provider-trust-bundle` and whose retired keys are `VERIFY_ONLY` for exact previously accepted bytes inside their frozen eligibility interval. Inventory acceptance authenticates immutable `HostReleaseProvenanceV1` before binding exact release, build, channel, and positive `inventorySequence`. Sole producer 0.8S consumes a reviewed closed `DistributionInventoryReleaseInputV1`; ordinary PR CI deterministically regenerates the unsigned body with zero diff and no production private key, while only a distinct non-exportable KMS/HSM signing service signs the exact domain-separated immutable semantic-parent bytes. Signature/envelope output is one mechanical child, and final CI recomputes from the recorded parent so no commit-SHA/signature cycle or semantic signing-child drift is accepted. Every inventory-changing train needs a new explicit sequence allocation, release input, and protected evidence or is `NO_GO`.
- Before composition, the Host persists `AcceptedDistributionSecurityStateV1`: the exact verified signed envelope/body, highest per-channel sequence/body digest, retained per-package version/definition/export high-water evidence, and permanent bidirectional package-name/module-ID tombstones. A digest alone is not recovery evidence, removed members do not erase security history, and rollback, same-sequence drift, version rollback, identity reuse, or same-version definition/export drift fails across restart. The nine existing packages still at ordinary version `0.1.0` rise to `1.0.0`; Create Loop becomes exactly `1.1.0` when 0.3 adds `./catalog-contract`; B is `1.0.0` as the 0.4 zero-contribution shell, `1.1.0` for the 2.1 backend, and `1.2.0` when 8.3 first adds its renderer/export definition.
- Persist user `installed`/`enabled` choices separately from derived effective availability: dependency loss yields `DEPENDENCY_UNAVAILABLE` and zero contribution without rewriting the enabled choice. All package activation and teardown use one durable lifecycle FSM: `INACTIVE -> ACTIVATING`, `ACTIVATING -> ACTIVE | QUIESCING`, `ACTIVE -> QUIESCING`, `QUIESCING -> DISPOSING | TEARDOWN_FAILED`, `DISPOSING -> INACTIVE | TEARDOWN_FAILED`, and `TEARDOWN_FAILED -> QUIESCING`. `ACTIVATING` builds only an inert, attempt-scoped, externally invisible staged contribution set. Under the sole generic graph lifecycle commit lock, the Host rechecks exact provider snapshots and atomically commits one durable revisioned `PublishedPackageSnapshotV1`; Main and renderer consumers privately stage, atomically apply or withdraw that complete revision, and reconnect from the Host-authoritative projection rather than eager composition. Manifest V2 supplies only signed generic resource declarations. The Host alone owns `PackageLifecycleRecoveryContractV1`, pre-acquisition durable resource claims, exclusive-Main startup normalization, and deterministic cleanup through fixed Host primitives. Restricted train 0.10R rewires the audited existing registrations, children, subscriptions, timers, workers, `HOST_NETWORK_LISTENER` resources, durable leases, and process-local disposers to those primitives without changing domain behavior. No package exports or executes a recovery program.
- Make Gate 0 dependency-correct and atomic: 0.1 then 0.2; immutable 0.7A, 0.8A, 0.8B, 0.8M, 0.8S, A-owned 0.8D, 0.8C, and 0.9 are the exact eight semantic producers that land only as platform foundation 0.8I plus one mechanical commit. Task 0.8D repairs the existing Git Checkpoints success envelope without changing its destructive result: the outer workspace-scoped success reports Broker metadata `changed:false`, meaning no caller-bound resource revision. No producer commit may merge, activate, or ship separately.
- Every top-level descriptor with exact `approval=confirmation`—for UI or Agent callers, every effect, and `global | workspace | resource` scope—uses one Host-orchestrated flow. Authenticated channel bootstrap returns one Host-minted current-epoch creation scope; the canonical client retains that scope and one stable request UUID for retries and calls only `createOrGetProtectedInvocation`. The Host binds the exact request and Host-derived target to a live `providerRegistrationId`, commits one non-evicting `AWAITING_CONFIRMATION` entry, then opens the trusted confirmation surface. Exact create retry, cancellation, read, and same-process replay observe the one closed entry FSM and cannot redispatch; provider quiescence contains every bound entry. Restart invalidates the creation scope, request retry, reference, invocation, challenge, receipt, and result before lookup. The old `requestProtectedInvocation`, generic-invoke, renderer/Agent-supplied confirmation, and destructive/external-write-only branches do not exist.
- Split phase control into development, basic merge, and capability activation gates. Atomic 0.8I still lands the exact eight foundation producers; after it, 0.10, restricted existing-resource train 0.10R, and generic Agent contract 0.11 form the basic platform. Once A's 0.14A public contract and B's 0.4/0.6 shell/contracts exist, B may develop pure P2 Ledger/FSM/reducer/policy/projection/lease/local-fake work on stacked branches with zero production registration or side effect. Task 0.12 waits only for 0.8I/0.10/0.10R/0.11 and the real B shell; task 0.15 is the P1/P2 foundation merge gate, after which 2.1/2.2 and P1 production may merge. - Add canonical Host workspace identity, the one SDK-owned acyclic `ComputeReservationV1`, Broker V2 exact owner ACLs, the closed `DOMAIN_MANIFEST | HOST_CORE` provider-provenance union, and exact versioned Host readiness evidence. Missing, disabled, or drifted readiness remains `STILL_BLOCKED`.
- Add one Host-private `LiveChildRegistrarV1` for protected Catalog and publication children, with exactly `OPEN -> CLOSING_SUCCESS -> SETTLED` and `OPEN -> REVOKING -> SETTLED`. `enterCommit()` and `enterPublish()` are typed facades over its one lease-entry transition; registration/lease admission close atomically, and the successful-return as well as throw/cancel/revoke races are tested in both orders.
- Add one durable Host Workspace Publisher for a single root-level filename, caller-stable `publicationId`, same-owner/workspace read-only `readPublication`, and exactly one active persisted `tempNonce`. In addition to the canonical registrar lease, it owns one expected-revision per-operation execution fence and a non-evicting single-flight under the application's existing single-Main-process boundary; a packaged second instance is rejected before publisher initialization, concurrent fresh confirmations or resumes have exactly one filesystem/native winner, and losers make zero filesystem calls and may only read/adopt the winner's durable state. Its closed public surface is limited to the exact `WorkspacePublicationReceiptV1`/`WorkspacePublicationPublicResultV1` field allowlists and generalized `REQUEST_REJECTED | PUBLICATION_FAILED | OUTCOME_UNCERTAIN`; exact diagnostics such as `TEMP_IDENTITY_CONFLICT`, nonce occupancy/type/identity observations, recovery identities, handles, paths, and execution metadata remain Host-private and cannot leak through text, events, IPC, logs returned to callers, or alternate errors. Lookup cannot acquire a fence or resume. `CLAIMED` commits before native create; only the claim-before-create crash window may resume, and only when the exact nonce path and final are authoritatively absent. Any existing nonce-path object while still `CLAIMED` is untrusted and no-touch: never open, truncate, adopt, rename, relink, or delete it. After `TEMP_STAGED`, a live `enterPublish()` lease must win and durably commit `PUBLISHING` before native no-replace publication. Only that exact `PUBLISHING` lineage may reconcile success, and both immediate completion and restart reconciliation must prove a regular, non-reparse, single-link final with the exact fenced identity/digest plus absence of the exact nonce path. Ship only `@sciforge/workspace-publisher-native`, Node-API ABI 8, with target-specific atomic no-replace primitives and source/packaged probes for macOS arm64/x64, Windows x64, and Linux x64.

- Add Workflow Evolution's separate SQLite Ledger, closed Run/Attempt/Gate/Operation state machines, total Catalog result reducer, structured documents, durable gates, receipts, restart reconciliation, and one FIFO controller-active Candidate lease. - Add durable Agent operations with one closed non-raw `RequestRebuildRecipeV1`. ## Capabilities

### New Capabilities

- `workflow-catalog-lifecycle`: Immutable Workflow definitions, releases, bindings, catalog revisions, candidates, Anchor generation, current-binding execution, and CAS writes.
- `workflow-evolution-control-plane`: Durable requirements, Coverage/Gap routing, document revisions, state transitions, gates, Teacher policy, and restart recovery.
- `workflow-candidate-governance`: Candidate isolation, policy validation, Builder/Verifier separation, evidence binding, human promotion, replay, and rollback.

### Modified Capabilities

- `official-workbench-domain-packages`: The Host adds canonical `WorkspaceIdentityV1`; strict Manifest V2 and one verified signed-inventory graph; the complete thirteen-then-fourteen `sciforge.official` release cohort while preserving six-plus-one Workbench product classification and every current contribution; purpose-aware `OfficialVerificationKeyV2` with three exact usages, historical-only `VERIFY_ONLY`, authenticated `HostReleaseProvenanceV1`, and isolated KMS/HSM 0.8S signing; complete accepted envelope/body/member anti-rollback state; canonical target-neutral export descriptors and SemVer monotonicity; persisted choice versus effective-availability separation; and one attempt-scoped staged/published/recoverable `QUIESCING`/`DISPOSING`/`TEARDOWN_FAILED` lifecycle. The Host owns its revisioned authoritative snapshot, Main/renderer stage/apply/withdraw/reconnect protocol, singular generic recovery contract, signed resource declarations, durable claims, and 0.10R primitive rewiring; packages own no recovery program. It also adds closed manifest-or-Host-core provider provenance and exact `{schemaVersion:1, entries}` readiness evidence. The independently activated durable publisher combines the canonical registrar with a per-operation execution fence and single-Main-process non-evicting single-flight, keeps `CLAIMED` nonce objects no-touch, commits `PUBLISHING` before native publication, and signs success only after exact final identity/digest/type/link-count plus nonce-absence proof.
- `capability-broker`: The wire contract advances atomically to V2; every existing `system` descriptor/caller is migrated to a signed manifest-owned outbound edge and matching non-empty exact target ACL/purpose or loses unused system audience, including `project-dag -> evidence-dag.view` and the typed `git-checkpoints.restore -> version-control.restore` Host-core-provider chain. The Git Checkpoints baseline repair keeps the successful destructive result while returning the correct outer `changed:false` metadata. Every UI/Agent top-level `approval=confirmation` action, across global/workspace/resource scopes and every effect, uses channel bootstrap plus stable request ID and the sole `createOrGetProtectedInvocation` flow bound to one live provider registration and closed non-evicting FSM. Same-process exact retry/read/replay never redispatches; provider quiescence contains its entries; restart rejects every old creation scope/reference/identity before lookup. Descriptors add strict Host-derived result delivery. The common live-child registrar enforces owner/workspace/purpose/process-epoch binding, `enterCommit()` for destructive children, `enterPublish()` for the sole approved external-write publication child, and settlement/revocation barriers.
- `agent-operation-governance`: Agent execution adds owner-persisted recipe plus Host-only ID/digest binding, durable pre-thread identity, atomic Host token allocation, a separate adapter-local pre-send acceptedness tombstone, token-unique `createOrGet`, authoritative `NOT_FOUND | RUNNING | TERMINAL | UNQUERYABLE`, operation-principal status/cancel/reconcile/result delivery, and closed domain projection consumption. The sole named production package/profile is `@sciforge/agent-operation-adapter` / `ATTESTED_EPHEMERAL_V1`, backed by independent pre-P4 0.11P qualification, sole 0.11S static purpose-scoped KMS/HSM-signed config/policy/trust/revocation bundle, fresh runtime attestation/revocation before credential/tombstone/raw access, OS-vault credentials, a single-shot isolated worker, and protected real-provider source/packaged platform evidence.
